## Срочная правка: пустая гора в .exe (2026-11-16, версия 0.0.11)

Автор написал: «горы нет, как только подходишь — пропадает». Причина: в собранной игре куча была пустой с версии 0.0.6. Файлы `data/dump_*.tres` были написаны руками, и при упаковке из них терялись массивы весов (PackedFloat32Array) — генератор не клал ни одного куска. Дальняя «шкура» рисовалась по высотам, поэтому издали гора была, а вблизи исчезала. В облаке игра запускалась из проекта, а не из пакета, и этого не видела.

Сделано:
- Оба файла пересохранены самим движком (ResourceSaver) — массивы доезжают.
- `scenes/debug/export_check.tscn`: проверка, которая запускается из упакованной игры (куча не пустая, модели и числа загрузились). Сборка на GitHub теперь гоняет её перед экспортом.

Правило: файлы .tres с типизированными массивами руками не писать — создавать скриптом через ResourceSaver или пересохранять движком. После любого нового файла данных — добавить его в export_check.

## Этап 3, часть 1: куча (2026-11-16, версия 0.0.6)

Сделано:

Форма — купол с буграми (свой целочисленный хеш и шум, без FastNoiseLite, чтобы совпадало на всех машинах). В ячейке кусок мусора или часть ценной вещи; вещь занимает блок ячеек (`ItemData.dump_cells`, холодильник лежит на спине в блоке 1×2×2).

- Засыпание: тело, пролежавшее 2.5 с, запекается в ближайшую пустую ячейку с опорой, сохраняя свою позу. Лимит живых кусков 110, сверх него мусор рассыпается в крошку.

- Фонарь на F (`PlayerCamera`, числа в `PlayerFeel`). Высота ступеньки персонажа 0.42 м: по ячейкам кучи идём как по лестнице, двойные ступени берём прыжком.

- Тест `tests/dump_test.tscn`: 28 проверок (сид, опоры, раскопка через ввод, завал, засыпание, подъём на вершину).

Решения:
- **Опоры по ячейкам, а не по чанкам**, как предлагал промт: так завал точно соответствует тому, что выдернули, и правило объяснимо игроку. Чанк остался единицей отрисовки и коллизии.
- **Решётка генерируется целиком и сразу** (34 мс на тестовую кучу): для сети хватит сида и списка изменённых ячеек.

Не сделано / слабые места:
- Завалы пока мелкие: на склоне над ячейкой редко больше 2–5 кусков. Крупный завал выйдет только если прокопаться вглубь. Нужно правило для боковой опоры и сползания склона.
- Кадры в секунду на настоящей видеокарте не мерил: в облаке только программный рендер. Гора 30–45 м потребует подгрузки чанков по расстоянию.
- Запечённый кусок твёрд по своей позе, а опоры считает по ячейке: возможны мелкие несостыковки.
- Вытаскивание мгновенное, без усилия и времени. Лопаты нет.
- Слои пока два (верх и глубина), а не три + «Дно».

Сделано:

- `scenes/player/ragdoll.gd` + `ragdoll_pose.gd`: свой рэгдолл из 11 тел на суставах (таблица PARTS), поза переносится на скелет модификатором, вставание — плавное смешивание обратно в анимацию.
- Рэгдолл включается в воздухе при скорости падения выше 13.5 м/с, при ударе о землю и по клавише Q (упасть нарочно). Камера сидит в голове рэгдолла и кувыркается вместе с ней. Встаём там, где остановилось тело.

Решения:
- **Свой рэгдолл вместо PhysicalBoneSimulator3D**: массы, лимиты и демпферы в одной таблице, тела — обычные RigidBody3D, которые потом синхронизируются по сети как предметы.
- **Меши названы mesh_body и mesh_head**: имя «head» конфликтовало с костью, импорт переименовывал кость в head_2.
- **Смещения таза в позах умножаются на HIPS_SCALE** (0.46): позы писались под человеческие ноги и перенеслись на короткие без переписывания.
- **Длина шага зависит от скорости** (`stride_walk`…`stride_run`), иначе на бегу ноги мельтешат.

Не сделано из этапа 1 (переносится): IK ног на неровном мусоре, отдельная анимация вставания (сейчас используется клип приземления), жесты.

Решения:
