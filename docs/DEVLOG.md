## Этап 1, часть 1: контроллер (2026-11-16)

Сделано:
- `scenes/player/`: `player_controller.gd` (движение и режимы), `player_camera.gd` (камера), `player_input.gd` и `player_input_reader.gd` (ввод отдельно от состояния).
- Разгон и инерция, бег, присед (не встать под низким потолком), прыжок с «койотом» и буфером, короткий прыжок при раннем отпускании.
- Ступеньки до 0.38 м без прыжка, перелезание через препятствие до 1.15 м по прыжку, подтягивание на уступ из прыжка (с земли достаём до ~2.7 м).
- Камера: качание от шага, наклон при стрейфе, просадка при приземлении, клевок при залезании, расширение обзора на бегу.
- Удар о землю быстрее 13.5 м/с (около 4 м) валит с ног: пока это падение камеры на землю, настоящий рэгдолл придёт вместе с моделью.
- Все числа в `data/player_feel.tres` (описание полей в `scripts/data/player_feel.gd`).
- Площадка `scenes/debug/playground_stage1.tscn`: лестница, ярусы 1/2/4/6 м, провал, низкий лаз, свободные ящики. Модель ящика из Blender.
- Автотест `tests/player_test.tscn` со сценарным вводом: 22 проверки (скорости, высота прыжка, ступеньки, залезание, лаз, падение).
- `scripts/debug/screenshot_tool.gd`: снимки экрана из командной строки для отчётов.

Решения:
- **Тело не вращается**, поворот хранится в `yaw`. Камера отвязана от физической интерполяции: позиция из сглаженного тела, поворот сразу из мыши.
- **Уступ ищем лучами на трёх глубинах** от края (0.2, 0.38, 0.55 м), берём ближайший подходящий: иначе игрок цеплялся за ящик, стоящий дальше.
- **После залезания 0.3 с не цепляемся снова**, чтобы не взлетать по ярусам без команды.
- **Ступенька щупается по направлению ввода**, а не по скорости: упёршись в край, скорость уже нулевая.

## Этап 0 (2026-11-16)

Сделано:
- Проект Godot 4.7.2, Forward+, физика Jolt, 60 тиков, интерполяция физики.
- Папки по структуре из промта. `art_src/` закрыта от импорта файлом `.gdignore`.
- Карта управления (клавиатура, мышь, геймпад): `scripts/autoload/input_setup.gd`.
- Автолоады: InputSetup, Settings, Save, Game, Net, Voice, Audio, DebugMenu. Net, Voice, Audio — заглушки.
- Отладочное меню F1: спавн предметов, время ночи, бессмертие, показ чанков, пинг, язык. Сверху строка FPS и активных тел (краснеет выше 150).
- Данные: `data/economy.tres` (нормы, цены), `data/items/*.tres` (предметы). Логика нормы: `scripts/systems/quota.gd`.
- Переводы RU/EN: `locale/strings.csv`.
- Blender-конвейер: `art_src/blender/lib/` (palette, geo, pipeline), `build_all.py`, первый предмет — чугунная батарея (788 треугольников).
- Палитра 256×256: `assets/textures/palette.png`, собирается из `lib/palette.py`.
- Аддон `addons/cvetmet_pipeline`: при импорте .glb ставит общий материал, `col_*` превращает в коллизии, `grip_*` в Marker3D.
- Тестовая сцена `scenes/debug/test_scene.tscn`, автотесты `tests/run_tests.gd`.
- GitHub Actions `.github/workflows/build.yml`: на каждый пуш в main собирает Windows .exe и выкладывает в Releases.

Решения:
- **Карта управления в коде, а не в project.godot.** Одно место для кнопок, позже проще сделать переназначение. Минус: в редакторе список действий пуст.
- **Предмет = RigidBody3D + модель из .glb.** `Item.setup()` переносит коллизии из модели на тело. Унаследованные сцены на каждый ассет пока не нужны, появятся вместе с дверцами и «разбитыми» вариантами (этап 2).
- **Материал один на всё**: палитра × вертексный цвет (грязь, ржавчина). В .glb материал-заглушка.
- **Сколы краски красим только на мелких гранях** (фаски, торцы): большая ржавая грань читается как полоса.
- **Превью рендерит Cycles на процессоре** (EEVEE без видеокарты не работает), 32 сэмпла, около 5 с на предмет.

Среда разработки в облаке:
- Blender: `pip install bpy==5.3.0` на Python 3.13, запуск `python art_src/blender/build_all.py`.
- Godot: готовые сборки не скачать, собирается из исходников тега `4.7.2-stable`.
- Видеокарты нет: кадры и ощущения проверяет только автор.
